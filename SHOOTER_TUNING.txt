SHOOTER TUNING — MOVE, TUNE, SAVE, LOOK UP

Panels browser setup, graphs and Capture/replay: see PANELS_SETUP.txt.

CURRENT ROBOT: ONE CONFIGURATION, SEVEN MOTORS, THREE SERVOS, PINPOINT
Use teamconfig8103.xml, the only bundled Team 8103 robot configuration.
Control Hub and Expansion Hub handle all seven motors. The bundled mapping is
  Front-left drive:  frontRight, Control Hub motor port 0.
  Front-right drive: backLeft, Expansion Hub motor port 2.
  Back-left drive:   frontLeft, Control Hub motor port 1.
  Back-right drive:  backRight, Expansion Hub motor port 1.
  Intake/transfer: intake, Expansion Hub motor port 0.
  Flywheel motor 1: smallShooter, Expansion Hub motor and encoder port 3.
  Flywheel motor 2: shooter2, Control Hub motor and encoder port 2.
  Front wedge: frontWedge, Control Hub servo port 0.
  Shot stopper: shotStopper, Control Hub servo port 2.
  Turret: turret, Control Hub servo port 4, standard positional Servo.
  Odometry: pinpoint, Control Hub I2C port 1 (goBILDA Pinpoint computer).
  Forward pod: Pinpoint X encoder port, goBILDA 4-Bar pod preset.
  Sideways pod: Pinpoint Y encoder port, goBILDA 4-Bar pod preset.
Both pods connect to Pinpoint; only the computer is listed in Configure Robot.
Keep Control Hub I2C port 0 free of Pinpoint; it shares the built-in IMU.
Run Pinpoint Check, then measure offsets and verify directions in Constants.
Pinpoint Check is the standalone odometry test; other enabled drive modes do
not use Pinpoint. Add Panels Telemetry + Field widgets for X/Y, heading, the
live robot marker and trail. In INIT, keep still and press Square to calibrate.
Wait for READY.
Optionally set PinpointCheck.startX/startY/startHeadingDegrees in Configurables
and tap Cross in INIT to apply a starting pose. Default (72,72,0) is a test reference;
use measured coordinates for the actual field location. Move the robot by hand
after START. See PANELS_SETUP.txt for access and the field coordinate convention.
Pinpoint wiring reference:
https://pedropathing.com/docs/pathing/tuning/localization/pinpoint

Install the full APK to update bundled XML configurations, then select the
updated configuration on the Driver Station or make the matching port edits
in the active configuration. A code-only reload does not update XML resources.
Old configurations saved on the robot are separate from bundled resources;
delete those manually in Configure Robot if you want only one saved choice.

Connect a DualShock 4 (PS4) or DualSense (PS5) to the Driver Station via USB.
Press Options + Cross to assign it as gamepad 1. If using a second controller,
press Options + Circle on that controller to assign it as gamepad 2. Confirm
the assignments on the Driver Station before starting an OpMode.

In Fixed Shot TeleOp, GP1 sticks drive and L1 toggles the wedge.
Circle toggles the shared intake/transfer motor. Hold Cross to shoot and
press Square to cancel.
Hold L2 to aim left or R2 to aim right. Trigger pressure controls how quickly
the target moves. Releasing the triggers, pressing both, or pressing Square
holds the last target. Release the triggers before resuming after Square or
if they were held through START.
In Panels > Configurables > FixedShotTeleOp, turretMinPosition and
turretMaxPosition default to 0.40 and 0.60 on the normalized servo range.
Set them to match the mechanism's travel. turretPositionPerSecond controls
the rate (default 0.25 units per second), and turretReversed swaps directions.
Set FixedShotTeleOp.wedge.stowedPosition/deployedPosition before INIT; the
wedge does not move until both positions are valid and different.
While Cross is held, the shared motor feeds only when the shooter is within
300 RPM of its target. Releasing Cross returns control to the Circle toggle.
The default target is 3000 RPM.

For continuous power/RPM bench work, use "Flywheel Tuning" (Tuning group).
Remove balls before INIT. The controls are live in INIT and after START.
Under Panels > Configurables > FlywheelTuning, use speed for motor 1 and
speed2 for motor 2. Each has its own setpointRpm, kP, kV and reversed, and
uses its own encoder feedback. RPM is the default and both targets start at
zero. Leave either target at zero to tune the other motor on its own.
In POWER mode, use power for motor 1 and power2 for motor 2.
In Panels Graph, select Target RPM and Current RPM for motor 1, and
Motor 2 Target RPM and Motor 2 Current RPM for motor 2. All four appear in
Telemetry. Both target readings are zero in POWER mode.
In Flywheel Tuning and Hardware Tuning, intakePower controls the shared motor.
Flywheel Tuning keeps that motor off when the shot stopper is unavailable.
In Hardware Tuning, INIT telemetry lists each control with the configured device
name and its detected connection. After START, shooterPower drives smallShooter
and shooter2Power drives shooter2. Use wedgePosition, shotStopperPosition, and
turretPosition for the three servos. Turret commands use the travel limits set
in FixedShotTeleOp. Use Pinpoint Check for the odometry computer.

FIELD DISTANCE CALIBRATION (PROTOTYPE)
Shooter Tuning remains disabled in source until field-calibration setup is ready.
Run "Shooter Tuning" in the Prototyping group. Open Panels at
http://192.168.43.1:8001 on the robot network and add the Field widget.
The map shows robot position/heading, recent travel, the selected CELL and
saved stations for that CELL. Current distance/RPM appear in Telemetry.

One fixed-geometry shooter serves both ball sizes using the same motor,
encoder and RPM controller. SMALL_POLLEN and LARGE_NECTAR retain separate
manual RPM presets and persistent distance tables.
The default motor is smallShooter. Change Launcher.shooter.motorName if
needed BEFORE INIT, then STOP/INIT after edits. Connect its encoder cable.
The example motor is a goBILDA 6000 RPM motor with 28 encoder ticks per motor
revolution; verify your hardware. Remeasure both ball tables for the new
mechanism before using saved distance lookup.
This mode also requires the four configured drive motors and Pinpoint.
The single base configuration includes Pinpoint on Control Hub I2C port 1.
Verify the pod model, directions and measured offsets before enabling this
field-based OpMode. No camera is required.

FIRST SETUP
1. Verify the chassis/Pinpoint setup and measured travel with Pinpoint Check.
   See FIELD_MAP.txt for the map axes. Coordinates are inches, (0,0) at the
   audience/red corner, +X right and +Y away from the audience. Heading zero
   points right; 90 degrees points away from the audience.
2. In Panels > Configurables > ShooterTuning select the raised target CELL
   (selectedCell). Both ball profiles use this same selected CELL.
   Start with frontal shots into that opening. The map uses nominal CELL
   coordinates from FieldConstants; confirm the real field reference.
3. Put the robot at a measured position. Enter startX, startY and
   startHeadingDegrees. During INIT, GP2 Square recalibrates Pinpoint while still.
   Wait for READY, then GP2 Cross applies the measured start pose.
   Panels edits alone never relocate the robot. Repeat this reference
   procedure after every new INIT or interrupted localization.
4. START with all run/drive controls released. Nothing spins automatically.
   Use GP1 D-pad left for small or right for big ball presets. Both use the
   same motor. Hold GP1 L1 for a low-voltage direction check. Release to stop.
   Confirm forward launch direction and positive encoder RPM;
   adjust Launcher.shooter.reversed before a new INIT if needed.
   Set Launcher.shooter.directionVerified=true only after checking it.
5. Tune the motor's RPM controller as described below, then build separate
   distance tables for the two ball sizes.

DISTANCE CALIBRATION
1. Choose the ball with GP1 D-pad left/right. Use MANUAL mode (GP1 Triangle toggles).
2. Move the robot to a shooting station. Hold GP2 L1 and use the left stick
   for robot-relative translation, right stick X for turning. Default drive
   scale is 0.35, configurable up to 0.5. You may also move it by hand with
   the drive controls released; Pinpoint still tracks movement.
3. Stop, aim at the selected CELL and test shots manually. Hold GP1 R2 to run
   the shooter. Change RPM with GP1 D-pad up/down (50 RPM per press,
   configurable rpmStep), or edit Launcher.smallBallRpm / largeBallRpm.
   Target changes update while R2 is held.
4. Once shots are repeatable, keep R2 held and press GP1 Cross to save.
   Save requires a healthy, explicitly referenced field pose, drive controls
   released, at least 0.3 seconds stationary, and measured shooter RPM settled
   at the requested target. It saves the TARGET RPM that was verified by the
   encoder, not an instantaneous noisy speed.
5. Look for SAVED in telemetry. The mode stops the shooter and the drive
   before writing the file; release R2 before spinning again. Holding Cross
   never repeatedly saves. A point within one inch of an old distance replaces
   it, so you can retune a station. GP1 Circle with all run/drive controls released
   undoes the last successful save from this run, including replacements.
6. Repeat at different distances. Each ball needs at least TWO different
   distances before lookup works. Start with near/middle/far stations and add
   stations wherever intermediate test shots need correction. Cover the
   actual shortest and longest distances you intend to shoot.
7. Press GP1 Triangle for LOOKUP, release the controls, then hold R2. As the robot
   moves, its current distance selects the two surrounding measurements and
   linearly interpolates RPM. All intermediate positions work without another
   save. Nothing writes to storage while simply moving in LOOKUP.

Example of the math only, NOT a measured shooting calibration:
  40 inches -> 2000 RPM; 60 inches -> 2600 RPM
  50 inches -> 2000 + (50-40)/(60-40) * (2600-2000) = 2300 RPM

WHAT THE TABLE MEANS
Distance is horizontal ROBOT-CENTER to selected CELL, in inches, both when
saving and looking up. A distance table needs far fewer measurements than an
X/Y grid. It assumes fixed launch geometry, consistent alignment and equivalent
raised CELL geometry. Saved X/Y/heading/CELL metadata places stations on the
map; it does not add angle or heading compensation. Each ball's table can be
used at the other nominally equivalent CELL locations. Keep the same measured
robot-to-launcher geometry and test angles before relying on it elsewhere.

The selected CELL is manual; the mode cannot tell whether a HIVE has tipped.
There is no automatic turret aiming, feeding or moving-shot compensation.
RPM may update while driving, but stop and aim before evaluating a shot.
Recalibrate after changing wheels, launch angle, gearing or other geometry.

Lookup never extrapolates: closer/farther than the saved range stops the
shooter and explains why. With no table or only one point it also
stays off. A lost field reference disables lookup and saving until a fresh
INIT reference. Switching ball, CELL or mode while holding a control requires
a release before that control can run again.
GP1 Square cancels shooter and drive. Release R2, both L1 buttons, and
Square to rearm.
Releasing R2 stops the shooter immediately. STOP ends the mode.

RPM CONTROL (ONE MOTOR, TWO BALL PRESETS)
Panels > Configurables > Launcher > shooter exposes the field tuner's controller.
These settings are separate from FlywheelTuning.speed used by Fixed Shot TeleOp.
These are voltage-based gains: kP [V/RPM], kI [V/(RPM*s)], kD [V/(RPM/s)],
kS [V], kV [V/RPM], kA [V/(RPM/s)]. Do not copy the old power-based bench
gains directly. The controller divides requested voltage by measured battery
voltage to produce motor power.

  feedforward V = kS + kV * referenceRPM + kA * referenceAcceleration
  feedback V = kP * error + kI * integral(error) - kD * measuredAcceleration
  motorPower = clamp(feedforward + feedback, 0, min(maxVoltage, batteryV))
               / batteryV

The shooter defaults to kP=.015 and kV=.0016, with kI=kD=kS=kA=0,
maxVoltage=3 V and an acceleration limit of 1000 RPM/s.
The conservative voltage ceiling may prevent reaching a requested shooting
speed; check outputLimited and raise the ceiling deliberately as appropriate
for the installed motor/mechanism before tuning high RPM.

Tune the motor at several speeds for both balls: start with I/D/A zero and P
low or zero, adjust kV for steady speed, then P for correction and recovery.
Add I only for persistent error, D if needed for damping, and A for ramp
tracking. Check recovery after actual shots. The controller uses software
PID/feedforward in RUN_WITHOUT_ENCODER; it does not stack Hub velocity control.

Graph shooter.*:
  targetRpm, referenceRpm, measuredRpm, feedforwardVolts, feedbackVolts,
  power, outputLimited and atSpeed.
Graph shooter.rangeInches and shooter.lookupRpm to inspect distance lookup.
Readiness requires the final ramp target plus an uninterrupted speed dwell
(default 250 ms within 150 RPM). Invalid feedback, missing encoder response,
excessive loop gaps or speed timeout stop output. Release before retrying.
Changing motor name, direction or encoder resolution requires STOP/INIT.
The field-tuning motor uses BRAKE at zero output and never commands reverse power.

PERSISTENCE
GP1 Cross saves BOTH tables together in the Control Hub's FTC settings directory:
  shooter-distance-tables-v1.json
The file is loaded on the next INIT and survives app/robot restarts. Save uses
an atomic replacement, file sync and verification. A failed write keeps the
current in-memory table; check the displayed error before continuing.
An unreadable/invalid file disables saving and lookup rather than overwriting
your measurements. Back up the file before repairing or replacing it.
The file includes a schema version, field reference coordinates and full pose
metadata. Incompatible field-coordinate changes require recalibration.
There are at most 100 stations per ball. Undo is one save deep and only for
the current run; the JSON file is the durable backup/export format.

Shot measurements persist automatically. Panels motor gains, hardware
settings and manual RPM proposals still need to be copied into source to
survive an app restart. No fabricated shot measurements ship with the code.
This is a tuning OpMode; a combined match shooting/feeding routine is separate.
