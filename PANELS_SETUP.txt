Panels setup for 8103

Install the full APK once after this migration:
    python3 tools/deploy.py --full
Then normal Sloth reloads can be used for code-only edits. Desktop validation
builds the app; it does not install anything on the robot. A Sloth-only reload
cannot remove Dashboard or add Panels' Limelight plugin to an installed APK.

Connect to the robot's Wi-Fi and open:
    Panels:        http://192.168.43.1:8001
    Pedro AutoTune: http://192.168.43.1:10158
Panels connects to its WebSocket service on port 8002 automatically. Replace the
IP if this robot uses a different network address.

Add Telemetry, Graph, Field, Configurables, Capture and Limelight widgets to a
Panels layout. Normal NextFTC OpModes and the standalone turret, shooter,
vision, Pinpoint and Brushland diagnostics share their telemetry with Driver
Station and Panels. AutoTune retains its own procedure UI.

Live settings

Panels Configurables exposes the tuning groups, including Launcher.shooter
gains, AxonTurret, HiveAutoAim, HiveVisionConfig, HivePedroConfig, MarrowConfig,
FieldMap and the diagnostic input settings. These are the same Java fields the
controllers use. PID gains, targets and settings read by the control loop can
be adjusted live. Settings already captured during INIT still require
STOP/re-INIT; this includes hardware names and the vision/Marrow setup.
Existing direction, geometry, travel, freshness and tuning gates remain active.
Record the final tune in source; editing runtime values does not edit Java files.

Useful graphs

In Flywheel Tuning, add the Telemetry and Graph widgets. Select Target RPM
and Current RPM for motor 1 and Motor 2 Target RPM and Motor 2 Current RPM
for motor 2 under Graph > Variables. The same readings appear in Telemetry
during INIT and after START. Both targets are zero in POWER mode.
Flywheel Tuning defaults to RPM with both targets at zero. Remove balls before
INIT.

The Shooter Tuning distance-calibration prototype provides these series:
    shooter.targetRpm / measuredRpm / referenceRpm / power
    shooter.feedforwardVolts / feedbackVolts / outputLimited
Use the complete dotted key for each series, for example
shooter.measuredRpm. See SHOOTER_TUNING.txt for measured pose setup and saves.

Axon Turret Test provides turret.actualDeg, turret.goalDeg, turret.profileDeg,
turret.actualDegPerSec, turret.profileDegPerSec and the existing power terms.

Field view

Run Pinpoint Check (Diagnostics) for the standalone odometry test. It acquires
only the Pinpoint computer. Add Telemetry and Field widgets: live X/Y in inches,
heading in degrees/radians, and a robot marker with heading arrow and trail
update during INIT and after START. Pitch/roll are also shown on supported
Pinpoint firmware; older firmware displays that they are unsupported.

In INIT, keep still and press gamepad 1 Square to calibrate the gyro. Wait for READY.
Under Configurables > PinpointCheck, enter startX, startY and startHeadingDegrees,
then tap gamepad 1 Cross to apply them. The default (72,72,0) places the test reference
at field center; enter measured coordinates to match the actual robot location.
Merely editing the settings does not reset the sensor. After START, move the
robot by hand. The Cross and Square controls are active only in INIT. The test
never acquires drive motors, mechanisms or a camera. STOP clears its field marker.
Fixed Shot TeleOp and Timed Leave + Park do not use Pinpoint.

Panels uses its bundled BIOBUZZ image, rotated into the team's audience-bottom,
red-left Pedro frame: bottom-left origin, inches, +X right, +Y away from the
audience, heading zero right. Keep the incoming BIOBUZZ / Pedro preset; remove
any saved manual coordinate overrides in the Field widget if necessary.

Robot pose, heading and recent trail use native Panels Circle/Line shapes.
Hive Marrow Test adds its purple route and configured obstacle; Shooter Tuning
adds the selected CELL and saved shot markers. Pose resets clear the trail.
Lost localization removes the robot and trail. No Dashboard drawing objects,
JSON conversion bridge or Dashboard field schematic remain in TeamCode.

The team publisher limits normal frames to 10 Hz. Faults, recovery and pose
resets publish immediately, bypassing the native manager's second throttle.
Status, field X/Y, heading and out-of-bounds warnings go through normal
Telemetry every loop because the pinned drawable API has no text primitive.
The field image does not supply a measured robot starting pose.

Capture/replay

Use the Capture widget to record and replay the normal Panels Telemetry and
Field streams while debugging. Native plugin frames include the robot trail,
routes and calibration markers. Capture requires operating the browser widget;
it does not start recording automatically when the robot starts.

Limelight

Panels owns the single Limelight proxy. Add its Limelight widgets for camera
video and the camera dashboard. The camera's web UI is also available through
http://192.168.43.1:5801 while connected to robot Wi-Fi. Panels forwards ports
5800 (video), 5801 (dashboard), 5805 (WebSocket) and 5807 (API) to the camera.
These services only forward camera traffic; the existing SDK camera polling,
pipeline selection, orientation updates and vision controls remain in TeamCode.

FTC Dashboard/Slothboard is removed from the dependency graph and installed app
build. Both Dashboard artifact groups are excluded to keep transitive copies
out. Panels' Limelight proxy is included; its earlier exclusion is removed.

Implementation

This project uses com.bylazar.sloth:fullpanels:0.3.2+1.0.13, the published wrapper
for Sloth/Load 0.3.2. RobotTelemetry uses Panels' native JoinedTelemetry and SDK
wrapper. NextFTC registers the stable Panels backend and flushes it once per
loop; standalone diagnostics retain their existing update() calls. The existing
Ivy scheduler remains the only command scheduler.

@Configurable exposes the tuning fields. Dashboard @Config annotations and
imports are removed. Private pose-transfer state is excluded from Configurables.

Verify after the full install: check telemetry during INIT, edit a tuning value,
check a numeric graph, and confirm Field Map corners and heading directions.
Open the Limelight widgets/dashboard, exercise STOP and switch diagnostics.
Desktop tests cover published APIs, native drawing frames and transforms;
browser/network/hardware behavior still needs this on-robot check.
